# C++ SDK — the engine-free core

Header-only C++17 with no engine types and no third-party dependency. Any C++
host can use it, and the Unreal plugin is built on it. It holds the part of a
C++ binding where the protocol bugs live, so it can be compiled and tested on a
machine with no engine installed:

| Header | What it is |
| --- | --- |
| `HaivenClient.h` | `FRestClient` and `FRealtimeClient` over the host's HTTP and WebSocket (`IHttpTransport`, `IWebSocketTransport`) |
| `HaivenHandoffCore.h` | `Haiven::Handoff::FCore`: the game login handoff (PKCE over a browser redirect), SHA-256 included |
| `HaivenProtocol.h` | the outbound envelope and its reply/event discriminant |
| `HaivenSessionCore.h` | `Haiven::FSessionCore`: auth handshake, re-auth, request recovery |
| `HaivenFrames.h` | server frames parsed from text and client frames written to text |
| `HaivenJson.h` | the JSON reader/writer the SDK uses: never throws, bounded depth, locale-independent |
| `HaivenChatCore.h` | `Haiven::FChatCore`: headless chat whose sends survive a reconnect |
| `HaivenRewardsCore.h` | `Haiven::FRewardClaims`: subscriber-reward claims whose retries reuse the claim id, with each refusal as a finite result; `Save` / `ExportSaved` / `ImportSaved` keep a claim id before link and the host posts it later; server grant and confirm requests |
| `HaivenPlayerAccess.h` | `Haiven::FPlayerAccess`: thin Phase 1 game-access request/reply helper and open player-status lookup, including founder, without coupling status to eligibility |
| `HaivenAnalyticsCore.h` | `Haiven::FAnalyticsBatcherCore`: bounded, contract-validated event snapshots, stable retry payloads, capped backoff, idle state, and finite configuration/input diagnostics; the host supplies timers and HTTP |
| `HaivenIdentityCore.h` | `Haiven::FIdentityCore`: strict MOTD/sign-in-method state, realtime-before-REST ordering, lifecycle invalidation, and same-browser account linking through an injected browser-context adapter |
| `HaivenRestApi.h` | REST request builders, generated by `codegen/emit_rest.py` |
| `HaivenWsApi.h` | WebSocket request builders and event table, generated by `codegen/emit_ws.py` |
| `Contracts/`, `Vocabulary/` | client contract types and open vocabularies, generated by `codegen/emit_contracts.py` and `emit_vocabulary.py` |
| `Contracts/HaivenRestTypes.h`, `Contracts/HaivenRestJson.h` | the REST bodies and replies (the gaming OpenAPI components) as structs in `Haiven::RestTypes`, and their codec, generated by `codegen/emit_rest_types.py`; `ContractsJson::FromJson`/`ToJson` read and write them |
| `Contracts/HaivenContractsJson.h` | `Read`/`Write` and `FromJson`/`ToJson` for every contract type over `HaivenJson.h`, generated by `codegen/emit_blueprint.py` |

Do not edit the generated headers; rerun `make emit`.

## Quickstart

Clone the header-only SDK into your project.

```sh
git clone https://github.com/haiven-dev/haiven-sdk-cpp.git third_party/haiven-sdk-cpp
git -C third_party/haiven-sdk-cpp checkout --detach 44480a20eeb40045505a81ef6b0c8240b1183dec
```

Add the source to your `CMakeLists.txt`. Replace `game` with your target name.

```cmake
add_subdirectory(third_party/haiven-sdk-cpp)
target_link_libraries(game PRIVATE haiven::haiven)
```

For a CMake installation, configure and install from the checkout with
`cmake -S third_party/haiven-sdk-cpp -B build/haiven` and
`cmake --install build/haiven --prefix ./third_party/haiven`. Point
`CMAKE_PREFIX_PATH` at that prefix and use `find_package(haiven CONFIG REQUIRED)`.

The SDK never opens a socket. Implement `Haiven::IHttpTransport` and
`Haiven::IWebSocketTransport` over the networking your game already has
(an engine's, a platform SDK's, libcurl, Boost.Beast, ...). Deliver every
callback on the thread that calls the clients, normally the game thread.

```cpp
#include "HaivenClient.h"
#include "HaivenHandoffCore.h"

Haiven::FClientOptions Options;
Options.BaseUrl = "https://api.haiven.gg/v0";
Options.RealtimeUrl = "wss://realtime.haiven.gg/v0";

// Sign in: open AuthorizationUrl in a browser, then hand the redirect back.
Haiven::Handoff::FConfig Config;
Config.EntryUrl = "https://id.haiven.gg/game-login";
Config.ExchangeUrl = "https://api.haiven.gg/v0/auth/handoff/exchange";
Config.IntegrationId = "your-integration";
Config.RedirectUrl = "yourgame://login/complete";
Haiven::Handoff::FCore Login;
std::string AuthorizationUrl, State, Error;
Login.Begin(Config, RandomBytes(32), RandomBytes(32), Now(), AuthorizationUrl, State, Error);
// ... later, with the redirect URL the browser returned:
Haiven::Handoff::FExchange Exchange;
Login.ConsumeCallback(CallbackUrl, Now(), Exchange, Error);
// POST Exchange.ToFormBody() to Exchange.ExchangeUrl, then:
Haiven::Handoff::FCredential Credential;
Login.StoreExchangeResponse(ResponseBody, Now(), Credential, Error);

auto Token = [&] { std::string Bearer; Login.GetAccessToken(Now(), Bearer); return Bearer; };

// One REST call, through a request the generated builders made.
Haiven::FRestClient Rest(Http, Options, Token);
Rest.Send(Haiven::Rest::GetAppsTags(), [](const Haiven::FHttpResponse& Response) { /* Response.Body */ });

// One realtime message: queued until the session has authenticated.
Haiven::FRealtimeClient Realtime(Socket, Options, Token, NewRequestId);
Realtime.Connect(Error);
Realtime.Session().OnEvent = [](const Haiven::FServerFrame& Frame, const std::string& Json) { /* ... */ };
Realtime.Send(Haiven::Ws::ChatSend(R"({"channelId":"c1","text":"hi"})"));
```

`RandomBytes` must come from the platform's secure random source. `Now()` is
`Haiven::Handoff::FTicks` since any fixed epoch, for example
`std::chrono::duration_cast<Haiven::Handoff::FTicks>(std::chrono::system_clock::now().time_since_epoch())`.

The credential is opaque and its absolute expiry comes only from exchange
metadata. `FCore::Restart` clears it and starts a fresh handoff for metadata
expiry, REST `401`, or WebSocket `auth.expired`; there is no web refresh path.

## Who uses it

The [Unreal plugin](https://github.com/haiven-dev/haiven-sdk-unreal) is built on it. A game installs that
plugin by copying its folder, so the plugin cannot include headers from here.
Instead it carries a byte-for-byte copy as the header-only External module
`sdks/unreal/Haiven/Source/ThirdParty/HaivenCpp`. Its `Haiven` runtime module
depends on that module publicly and adds the engine glue: `IWebSocket`, HTTP,
`FString` and `FDateTime` conversion, the game-thread boundary, and the Blueprint
nodes. It parses and writes frames with `HaivenFrames.h`, and its
`Haiven::FHandoffCore` adapts `Haiven::Handoff::FCore`, so the engine and every
other C++ host run the same rules.

This directory is the source of truth. After editing a hand-written header, run
`make vendor-cpp`. Every `make emit*` target revendors on its own, and
`make check-cpp-vendor` (part of `make check`) fails when the copy has drifted.

C++ is a target in its own right: `codegen/features.py` declares the `gaming/cpp`
target (runner `cpp`), and `docs/features.md` has a C++ column beside Unreal's.

## Running it

```
make check-cpp        # every test under test/, at -O2 -Wall -Wextra -Werror
make check-cpp-cmake  # the CMake package: ctest, install, and a find_package consumer
make check            # everything, from the repository root
```

`verify.sh` builds each `test/*_test.cpp` with an ordinary `g++`/`clang++` and
runs it. That includes the scripted-server client corpus from
`conformance/gaming-client/v0`, run through
`FRealtimeClient` over a scripted socket, so every frame crosses the text
boundary. `scripts/check-cpp-cmake.py` builds the same tests through CMake,
installs the package, and builds `test/consumer/` against the install. CI runs
it under GCC, Apple Clang and MSVC. Both skip loudly without their toolchain.

`test/client_conformance_test.cpp` answers to both `gaming/cpp` and
`gaming/unreal` waivers, because Unreal's session core is this SDK.
`test/conformance_test.cpp` is the Unreal profile's fixture runner
(runner `unreal-automation`). It drives
`FSessionCore` against the real `cmd/wsfixture` over the POSIX sockets in
`test/conformance/`, and `make check-unreal` runs it through
`scripts/check-unreal-conformance.py`.
